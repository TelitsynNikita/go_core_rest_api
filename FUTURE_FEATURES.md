# Идеи и фичи на будущее

Направления развития (без обязательства сроков). При реализации имеет смысл дробить на отдельные задачи и PR.

## Безопасность и контракт API

- **Allowlist имён функций БД** или строгая валидация идентификатора перед подстановкой в `SELECT ...`, чтобы исключить SQL-инъекции при расширении источников конфигурации.
- **Возврат `json.RawMessage`** из слоя БД (или отдельный тип) с парсингом на уровне хэндлеров — проще версионировать ответы и писать тесты.

## Надёжность и эксплуатация

- **Оборачивание ошибок** (`fmt.Errorf` с `%w`) для цепочки scan → unmarshal и запросов к БД.
- **Метрики**: время запросов к БД, состояние пула (опционально OpenTelemetry / Prometheus).
- **Graceful shutdown** Fiber и закрытие `sql.DB` при остановке процесса.

## Конфигурация и DSN

- Сборка строки подключения через **URL** (`postgres://...`) и корректное экранирование пароля со спецсимволами.
- Вынос **настроек пула** в отдельную секцию или единый блок `pool` в JSON для ясности.

## Производительность

- Кэширование подготовленных запросов там, где имена функций ограничены заранее (осторожно с динамикой `SELECT имя()`).

## Разработка

- Интеграционные тесты с **testcontainers** или локальным PostgreSQL для `SelectFunction` и регистрации маршрутов.
- Пример **Docker Compose** (приложение + Postgres) для локальной отладки.

## Документация

- OpenAPI/Swagger, генерируемый из YAML-описания API (если схема стабилизируется).
